# Extract Mobbin 4, then let code rule

Treat [Prototype Mobbin 4](https://claude.ai/artifact/Nd3ZoK9rHyAgWfak2xJnn3) as the visual authority only until each value and component has been extracted, then make code canonical and keep the canvas as the place to explore and propose changes. The canvas cannot stay the source of truth: only 16 of its 34 boards qualify as canon, every file redeclares its own tokens, nothing is shared, and all styling sits in **8,286 inline `style` attributes** ([audit-out/s1.txt][s1]). What should survive is the language inside it: named role values, quiet uppercase grey section labels, monospace tabular prices, a liquid-glass navigation layer and a catalogue built around long price lists and WhatsApp rather than a cart. Hover, focus, errors, form validation and every width between 360 and 1440 have to be designed new. The recommended stack is DTCG tokens built by Terrazzo, Tailwind v4 with native HTML and Base UI, Storybook on preview deployments, and lint, axe and visual review as the gates that replace Figma's approval role. The 14 December closure of standalone Claude Design is confirmed, but this canvas is already an Artifact, so its boards are not the exposed part; chats, comments, any unmoved projects and a fragile image dependency are. No long-term study of a Figma-free design system exists, so the rollout below is a reasoned synthesis, not a proven recipe.

## Mobbin 4 should hand over authority piece by piece

The canvas earns its authority on design intent. It holds a curated type ladder, consistent core colours and 3,521 notes explaining why things changed. Its structure disqualifies it as a permanent source. `<dc-import>` appears **0 times** ([audit-out/s11.txt][s11]), and **67.6% of canon bytes sit in lines shared by two or more boards** ([audit-out/s10.txt][s10]). The help centre exists as four divergent copies of about 48 KB each. File names mislead too: `SalinanBlogM4` is titled "Blog", and three "Detail Artikel" boards are functional duplicates ([audit-out/s2.txt][s2], [audit-out/s3.txt][s3]). Artboards also run on a proprietary layer of `support.js`, `{{holes}}` and classic-JS `DCLogic` ([Design type](https://claude.ai/artifact/QKN21svewxgyPb6SYRqWnd)), so the markup should be rebuilt while its values and interaction specs become the specification.

Authority should then move one way. Anthropic's tooling already assumes this: a `/design-sync` system "is read-only for everyone", and changes happen in code ([Design System type](https://claude.ai/artifact/5M7UeXXcx16TP3vzVFNDzd)). A canvas holds a copy of a system that "never changes by itself" ([Design type](https://claude.ai/artifact/QKN21svewxgyPb6SYRqWnd)). One team's dual Figma and code systems caused "constant drift" until the system lived only in code ([Zheng](https://changying.substack.com/p/case-study-from-figma-first-to-code)), and BILL keeps Storybook as its single source so docs cannot fork ([BILL](https://www.bill.com/engineering/how-we-made-our-design-system-bilingual)). The best counterexample is Cisco, where "the HTML prototype became the single source of truth", yet that was one internal tool with no shared system or described governance ([Cisco](https://blogs.cisco.com/cisco-devnet/design-to-code-ai-handoff-workflow)). Third-party claims of two-way `/design-sync` conflict with the read-only behaviour above, so treat them as unverified ([workflow notes][workflow-notes]).

The rule to write down is simple: a token or component is canonical on the canvas until it merges, and canonical in code afterwards. New ideas start on the canvas labelled "proposed" and return as a changelog plus a pull request. Any canvas showing a shipped pattern is not evidence of what ships; Storybook and previews are.

Dropping Figma removes a parallel library, and that is the well-evidenced part. Public accounts describe Figma's role narrowing far more often than its removal, and all but one strong case had code before it had canvases ([workflow notes][workflow-notes]). SMSP is going further than most, so it will pay some costs first-hand. The losses are concentrated:

| Figma function | Replacement | What is genuinely lost |
|---|---|---|
| Library browsing | Storybook, plus a generated design system artifact | Dragging instances from a panel. Mounting real components on a canvas needs a bundle and an agent |
| Multiplayer critique | Canvas co-presence plus a scheduled live review | Reliable co-editing: "still basic and may not work reliably" ([Get started](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)) |
| Comments | Canvas comments while exploring, preview or PR comments once code exists | Durability, so copy decisions into `docs/decisions/` |
| Version history | Git, plus artifact versions | Possibly nothing, but the docs conflict: "doesn't have version history yet" ([Get started](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)) versus "each publish becomes a version" ([Claude Code docs](https://code.claude.com/docs/en/artifacts)). Test it |
| Design approval | Visual diff review on a PR | Library ownership by designers who do not use Git, since synced systems cannot be edited on their page |
| External review | Preview URLs | Open commenting: public-link artifact viewers cannot comment ([Claude Code docs](https://code.claude.com/docs/en/artifacts)), and Vercel comments need accounts ([Vercel](https://vercel.com/docs/comments)) |

Claude Design and Claude Code cover exploration and production, so resist adding another canvas. Design Systems are in beta and unavailable on Free ([Academy](https://academy.claude.com/tutorials/create-a-design-system-with-claude)), and the whole product went from launch to merger in five months, so the Git copy is the real hedge. Penpot earns a place only as contingency for non-coders or exit insurance. Keep Figma view-only for one cycle after exporting `.fig` files and brand SVGs, because those files open only in Figma ([Figma Help](https://help.figma.com/hc/en-us/articles/360039826814-Delete-your-Figma-account)).

## Tokens should encode SMSP's role values, not a generic grid

Author in DTCG 2025.10, the first stable version, which is a Community Group report rather than a W3C Standard ([DTCG](https://www.designtokens.org/tr/2025.10/)). Build with **Terrazzo 2.10, pinned exactly**. In the research team's smoke test it handled every fixture feature, while Style Dictionary 5.7.1 silently ignored `$extends` and resolver files and wrote wrong values for `$ref` ([token notes][tokens-notes]). Silent failure is worse than a missing feature, because it ships bad CSS. The main risk is concentration, with one maintainer at 602 commits and the next human at 21 ([Terrazzo](https://github.com/terrazzoapp/terrazzo/graphs/contributors)). A portable subset, using curly aliases and no `$ref`, `$extends` or gradient tokens, keeps Style Dictionary available as the exit.

Use private primitives, public semantics and component tokens only by exception. One brand, one platform and one repo do not justify Spectrum's scale. Claude's design system page needs a translated output: its `tokens.json` uses a list shape, and a DTCG map "is valid JSON the page CANNOT read" ([Design System type](https://claude.ai/artifact/5M7UeXXcx16TP3vzVFNDzd)). Generate that file so it can never be hand-edited.

Two of the notes disagree on spacing, and the canvas wins. The token research recommends a 4px-based scale, but it did not examine this canvas. The audit finds only 32% of mobile and 45% of desktop values fit 4px, and the core values 15 and 30 never will ([audit-out/s6.txt][s6]). Half-gutters depress those figures, so they rule out a strict grid rather than measure it. Since Mobbin 4 is the declared authority, name its roles, add micro steps of 2, 4, 6, 8 and 10, and snap one-offs through a reviewed mapping table. Do not point an extractor at raw margins: it would misread the "6px ×491" peak, which is an artefact of the half-gutter convention.

The root font size needs a deliberate decision, because it collides with the stack. The canvas sets `html{font-size:62.5%}`, production sets `font-size:10px` ([smsperkasa.com](https://smsperkasa.com/), checked 3 Nov), and the older contract says to divide by 10. All three agree that 1rem is 10px, so keep that base, using the percentage form, because a fixed pixel root ignores a reader's browser font setting. The catch is that Tailwind and shadcn output assume 16px: the token notes' sample `--spacing: 0.25rem` would mean 2.5px here, while a `90rem` breakpoint stays 1440px because media queries ignore the root size. This reasoning comes from standard CSS rather than the sources, so prove it in the first spike.

Ship hex or `rgb()` and author in OKLCH only if ramps become necessary, since Indonesian browser versions cannot be established from public data ([token notes][tokens-notes]). Use WCAG 2.2 as the only contrast gate, because the WCAG 3 draft says its algorithm "is yet to be determined" ([W3C](https://www.w3.org/TR/wcag-3.0/)). Name pairs as `x` and `on-x` so CI gets a mechanical list to check, set `--*: initial` so Tailwind's defaults disappear, and hand-review the theme map, because Terrazzo's Tailwind plugin produced doubled names under a naive config ([token notes][tokens-notes]).

The largest design gap is states. Canon has **no hover style on any button, link or card, 3 `:focus-visible` rules and 28 `outline:none` declarations**, along with no form validation, toast, skeleton, tooltip or accessible modal handling ([audit-out/s6.txt][s6], [audit-out/s14.txt][s14], [audit-out/s15.txt][s15]). The 10 desktop boards are, in state terms, touch designs at 1440. The older contract shortens this work: it already defines six states, a 2px focus ring at 2px offset, icon-plus-label alerts, and "Stok menipis" and "Harga indikatif" patterns that Mobbin 4 lacks ([SMS Perkasa v5](https://claude.ai/artifact/Cx6beToCZPtSCVnET3bv33)). Base UI gives ARIA and keyboard behaviour, but you still own visible focus, contrast and names ([Base UI](https://base-ui.com/react/overview/accessibility)). Also fix what the audit found structurally: `<main>` is missing on 6 of 16 canon boards and `SkuDetailM4` has no `<h1>` ([audit-out/s7.txt][s7], [audit-out/s14.txt][s14]). Enable axe's `target-size` rule explicitly, since it is off by default ([axe](https://raw.githubusercontent.com/dequelabs/axe-core/develop/doc/rule-descriptions.md)), and keep manual TalkBack checks, because axe finds only about 57% of issues by volume, a vendor figure ([Deque](https://www.deque.com/blog/automated-testing-study-identifies-57-percent-of-digital-accessibility-issues/)).

Responsive behaviour also needs new design. Page roots are fixed at 360 or 1440, and canon has just 2 `min-width` queries ([audit-out/s11.txt][s11]), so at least 768 and 1024 must be defined, with the older contract's 860px rule as one candidate. Do not assume mobile dominates: StatCounter shows Indonesia at **58.29% desktop and 41.22% mobile**, a figure skewed by which sites carry its tracker ([StatCounter](https://gs.statcounter.com/platform-market-share/desktop-mobile-tablet/indonesia)). Your own analytics should settle this, and they are not in the research.

Budgets should use Indonesia's slow tail of 6.4 Mbps and 75 ms at P75, not the 63 Mbps speedtest median ([Russell](https://infrequently.org/2025/11/performance-inequality-gap-2026/), [Databoks](https://databoks.katadata.co.id/en/technology-telecommunications/statistics/6a604db869d80/mobile-internet-download-speed-in-southeast-asia-june-2026-brunei-leads)). The researchers propose design-system first-load JS of 40–50 KB brotli and critical-path JS of about 200–250 KiB; these are starting points to validate on real phones. Remove `_jarakHitung`, the runtime engine that measures heights and rewrites section margins on 7 canon mobile boards ([audit-out/s8.txt][s8], [audit notes][audit]). A note records five tuning attempts defeated by it, and it can shift layout. A static section token is the simpler route, unless you value the optical effect enough to keep it.

Start documentation with Storybook only. The notes disagree here, with one recommending a Fumadocs site and another warning against a bespoke docs site early. They reconcile on sequence: one MDX page per component for the first 10–15, a stable URL per component, state and viewport as the handoff link, and Fumadocs only when guidance outgrows MDX. One constraint needs an early test: artboards supply React 18, and a bundle carrying its own React cannot share the page's ([Design type](https://claude.ai/artifact/QKN21svewxgyPb6SYRqWnd)). A production app on React 19 would need a separate canvas build target.

## Ninety days, one named owner, and machines doing the policing

Practitioners agree on small scope and a real pilot, but disagree on whether tokens or components lead ([workflow notes][workflow-notes]). Here the extraction runs both at once, and **the pilot should be the product price list and SKU detail**. Those pages are unambiguous on the canvas, are among the most linked and hold the distinctive patterns. No published 30/60/90 exists for this path, so these dates are judgement.

| Window | Work | Exit test |
|---|---|---|
| **Week 1** | Back up as above, name one owner, and declare the authority rule in writing. Spike the unknowns: version history, zip portability, `/design-sync`, the React 18 bundle, the 10px root with Tailwind, and a designer-opened PR | The backup restores, images included |
| **Days 8–30** | Scripted inventory of canon boards, reviewed token set, screenshot baselines from the live canvas at 360 and 1440, first 3–5 components (Button, Price, price row, fraud ribbon, field), preview deploys, first design system sync | A non-coder can comment on a preview, and a designer can land a small change with help |
| **Days 31–60** | Ship the pilot from system components only, growing to 8–12 as it demands. Storybook with all states, axe and visual snapshots in CI, short agent instructions, generated component metadata, raw-value lint in warn mode, 5–10 prompt evals | The full change flow has run twice: canvas proposal, changelog, PR, preview, merge, sync |
| **Days 61–90** | Lint to error for new code, deprecation policy, home and blog once decided, stale-canvas check, retrospective with designers | A decision, based on real gaps, about cancelling Figma |

Governance should stay small and lean on machines. Most systems have 2–5 people who also do product work ([NN/g](https://nngroup.com/articles/lean-design-system-teams)), so one accountable owner, CODEOWNERS on tokens and components, a decisions folder and a compressed flow are enough: check the system, classify as one-off or system, propose, review on preview, merge with a changelog, sync. Promote a pattern at its second or third real use. Agents open PRs and never merge them. Bus factor is the top structural risk, and generated docs and runbooks are the mitigation.

For agents, the evidence favours short context plus deterministic refusal over long instructions. ETH Zurich found context files generally do not improve task success and raise cost by over 20% ([arXiv](https://arxiv.org/abs/2602.11988)), while Vercel found a compressed docs index helped with knowledge the model lacked ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). So write a short `CLAUDE.md` holding only what is non-standard, usage rules in the design system README, generated metadata, a lint that bans raw values, and evals with Indonesian strings. Anthropic confirms that a prompt outranks the design system ([Claude Code docs](https://code.claude.com/docs/en/artifacts)), which is exactly why rules need something that can refuse them. Add an MCP server last, because BILL's outages stalled agents ([BILL](https://www.bill.com/engineering/how-we-made-our-design-system-bilingual)). Do not attempt two-way sync, multi-brand architecture, a large library, a bespoke docs site or big-bang rollout early, and do not require designers to become coders; ServiceNow reports that graphic designers struggled with how much coding remained ([ServiceNow](https://www.servicenow.com/community/innovation-office-blog/idea-to-code-in-an-ai-world-do-we-need-figma/ba-p/3394865)). AI output never counts as accessibility evidence: in a vendor-sponsored test, all 15 AI-built sites failed WCAG Level A ([VentureBeat](https://venturebeat.com/ai/we-asked-five-ai-tools-to-build-accessible-websites-all-15-sites-failed)).

Read the numbers with these limits in mind. Audit counts are source declarations rather than rendered instances, since no board was rendered, so computed section gaps and real on-screen contrast are unmeasured and no axe run exists. Scripts and outputs are in [audit-evidence/audit-scripts][scripts] and audit-evidence/audit-out. Tool comparisons are mostly written by competitors, most Claude Design criticism predates the September merge, and the team accounts are under 12 months old with few outcome metrics. Figma's Q2 revenue still grew 48% ([SEC filing](https://www.sec.gov/Archives/edgar/data/0001579878/000162828026053331/q226pressrelease.htm)), so nothing here shows a market leaving. The token test was the research team's own smoke test, not a conformance run. Team size, device mix and conversion data were not available and would change the plan. The checks marked 3 November, on the production site, the parent canvas and the asset stores, were added during this synthesis and go beyond the notes.

## Conclusion

Choosing Mobbin 4 as the source of truth is less a tooling choice than a repeal. An earlier contract, its repo and a lint rule deliberately kept the canvas's weights and sizes out of production, and the canvas's notes respected that boundary. SMSP has effectively been running two design languages on purpose, so the real first decision is retiring one, which is why the typeface question matters more than any tool in this report. The notes also suggest the gap was never discipline: 3,521 dated decisions show unusual care, yet the older contract had a machine gate on code and none on the canvas, so the canvas could move freely, and its claims of parity with code could not be verified in this audit.

Two practical implications follow. Those notes are the most valuable asset to migrate after the values themselves, and mining them into decision records would give both people and agents a rationale that few design systems ever have. And because token extraction barely changes whichever home and blog boards win, nothing needs to wait for those decisions: the backup can happen this week, and the first thing worth shipping is not a button library but an accessible price list.
